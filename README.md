# social-intelligence

A Python social media analytics pipeline that collects posts from **Telegram**, **X (Twitter)** and **YouTube**, normalizes them, and runs sentiment + emotion analysis (transformers), demographic inference, trend detection and influence-network analysis. Everything is stored in an SQLite database (`social.db`), summaries are written as Markdown reports, and a Streamlit dashboard visualizes the results.

## Quick start

```powershell
cd social-intelligence
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Create a `.env` file from the template:

```powershell
Copy-Item .env.example .env
# then fill in your API keys (see "Environment variables" below)
```

Run the pipeline (collects Telegram + X posts and auto-discovers YouTube videos for the topic, then analyzes everything):

```powershell
python run_pipeline.py --topic "AI Agents"
```

Open the dashboard in a second terminal:

```powershell
streamlit run dashboard\app.py
```

> **First run is slow** — the sentiment and emotion models download the first time you run analysis (`cardiffnlp/twitter-roberta-base-sentiment-latest` and `j-hartmann/emotion-english-distilroberta-base`). Later runs use the local cache.

## Running the pipeline

```powershell
# Collect + analyze (default)
python run_pipeline.py --topic "AI Agents"

# Collect only, skip analysis
python run_pipeline.py --topic "AI Agents" --no-analyze

# Skip collection, re-analyze data already in the DB
python run_pipeline.py --topic "AI Agents" --no-collect

# Custom Telegram channels / X queries / explicit YouTube URLs
python run_pipeline.py --channels @aipost @KDnuggets --x-queries "AI Agents" "LLM"
python run_pipeline.py --topic "AI Agents" --youtube-urls "https://www.youtube.com/watch?v=VIDEO_ID"
```

### YouTube topic discovery (on by default)

The pipeline searches YouTube for videos matching your `--topic`, then extracts comments from the ones it hasn't seen yet.

```powershell
python run_pipeline.py --topic "AI Agents"          # 5 videos, 100 comments each (defaults)
python run_pipeline.py --topic "AI Agents" --yt-max-videos 8 --yt-comments 150
python run_pipeline.py --topic "AI Agents" --no-youtube-search   # disable discovery
python run_pipeline.py --topic "AI Agents" --yt-refresh          # force re-extract cached videos
python run_pipeline.py --topic "AI Agents" --yt-budget-units 2000  # per-run quota cap
```

Discovered videos are cached in the `youtube_videos` table (keyed by `video_id + topic_query`), so re-runs only fetch comments for **new** videos. Quota spend is ledger-tracked in `youtube_quota.json` (gitignored), resetting at UTC midnight against the 10,000-unit/day limit.

### Skipping analysis stages

```powershell
python run_pipeline.py --skip-emotions --skip-demographics --skip-network --skip-narrative
```

## Environment variables

Copy `.env.example` to `.env` and fill in your keys.

- `TG_API_ID`, `TG_API_HASH` — Telegram API credentials from https://my.telegram.org (required for Telegram collection; the first run creates a `session_name.session` you authenticate once).
- `YOUTUBE_API_KEY` — YouTube Data API v3 key from https://console.cloud.google.com/apis/library/youtube.googleapis.com (enable "YouTube Data API v3" and create an API key). Without it, YouTube collection is skipped with a warning — the pipeline never crashes.
- `LLM_API_KEY` — optional Google Gemini key from https://aistudio.google.com/apikey, used for the narrative report. If unset, the report falls back to a deterministic template.
- `LLM_MODEL` — optional Gemini model override (default `gemini-3.5-flash`; `gemini-2.5-flash` is retired for new API users).

- `SOCIALFETCH_API_KEY` — Social Fetch API key from https://app.socialfetch.dev (required for X collection). Collection is metered: discovery costs 1 credit, each profile timeline page costs 1 credit, and the default run (`1 + 3 profiles`) is capped at 4 credits. The API accepts `limit=100` but a live run returned 20-22 tweets per profile page, so budget roughly **~20 tweets per credit**. The free 100-credit grant is tracked in a gitignored, lifetime-cumulative `x_credits.json` and never silently refills.

## What it produces

- **`social.db`** (project root) — SQLite database with `posts`, `sentiments`, `emotions`, `demographics`, `trends`, `network_nodes`/`network_edges`, `narratives`, and `youtube_videos` tables. All posts share one uniform schema (`id, platform, author_id, author_handle, text, raw_text, created_at, collected_at, parent_id, topic_query, reactions, shares, replies, views`).
- **`reports/<topic>_<timestamp>.md`** — Markdown narrative report generated by the final pipeline stage.
- **Dashboard** — Streamlit app with sentiment/emotion distribution, demographics, rising terms, influence network, and the narrative report.

## Architecture

```
collectors/        Telegram (Telethon), X (Social Fetch) and YouTube (Data API v3) scrapers
normalizer/        Text cleaning, dedup, tokenization
analytics/         Sentiment + emotion (HuggingFace transformers), demographics,
                   trend detection (TF-IDF), network analysis (NetworkX),
                   narrative report (Gemini API or template)
database/          SQLite schema and CRUD (social.db)
dashboard/         Streamlit UI
run_pipeline.py    CLI entrypoint wiring the stages together
tests/             pytest suite (isolated DBs under .test_tmp/, mocked models)
reports/           Markdown narrative reports written by the pipeline
```

The DB path is anchored to the project root, so the pipeline and the dashboard always share the same `social.db` regardless of where you launch them.

## Key facts worth knowing

- **Sentiment/emotion models download on first run** — slow startup until cached; text is truncated to 512 tokens before analysis.
- **YouTube discovery is incremental and quota-aware** — per-run cap `--yt-budget-units` (default 2000 units ≈ 5 videos/topic) plus a daily ledger; a `403 quotaExceeded` aborts remaining videos with a clear message. `search.list` costs a flat 100 units; `commentThreads` ≈ 1 + items.
- **X collection is metered and best-effort** — `--x-queries` are profile *discovery* queries, not tweet searches. Each profile yields **~20 tweets for 1 credit** in practice; `private`/`not_found` profiles bill and return nothing, which is why pulled handles are cached in `x_profiles` and skipped free on re-runs. `--x-dry-run` prints the exact plan and cost without spending.
- **X results are relevance-filtered, because discovery returns promoters** — a live "AI Agents" run surfaced giveaway/token accounts and ~48% of the collected tweets were promotional. Two filters run in `collectors/x_collector.py`: a **pre-spend** filter drops profiles whose name/bio lack a topic term or carry promo markers (a rejected profile costs **0 credits** instead of 1), and a **per-tweet** filter drops giveaway/airdrop/presale posts. A profile whose timeline is ≥50% promo is dropped entirely but still cached, so it is never re-billed. Both are heuristics that can over-filter: `--x-no-require-topic` relaxes the topic requirement and `--x-allow-promo` disables the promo filter.
- **Telegram auth** — the `.session` file is created on first collection; delete it to re-authenticate.

## Testing

```powershell
python -m pytest
```

The suite runs fully offline: HF models are mocked, each test gets an isolated SQLite DB under `.test_tmp/`, `load_dotenv()` is no-op'd, and real API keys are scrubbed from the environment for the whole session — the real `social.db` and `.env` are never touched.
